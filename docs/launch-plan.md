# OpenAA 微信小程序：上线优先架构与路线（2026-10-30）

## 原则
- 优先发布可用的只读 MVP，之后小步迭代。
- 微信原生小程序 UI，复用 OpenAA 现有公共 API 与 Supabase 唯一业务数据库。
- 小程序与主站使用独立 GitHub 仓库；主站 API 变更需兼容并接受审查。
- 客户端绝不保存 Service Role、AppSecret 或其他服务端凭据。
- GitHub 合并不等于微信部署或审核通过。

## 组件边界
1. 微信客户端：展示、列表状态、分享、筛选、基础工具。
2. OpenAA 服务端 API：公开列表与详情、分页、审核过滤、公开字段投影、未来认证桥接。
3. Supabase：既有数据库、存储和权限系统。
4. 微信公众平台：账号资质、备案、服务类目、合法 request 域名、隐私说明、审核和发布。
5. GitHub：版本管理、PR、测试和变更审计。

## V1.0 上线范围（只读）
- 首页：四频道入口、最新招聘、加载及异常状态。
- 招聘、房屋、二手、本地服务：真实公开列表、分页、基础筛选、详情。
- 稳定分享：按 channel + id 独立加载详情，冷启动与失效场景可处理。
- 基础实用工具：温度和距离换算。
- 反馈/联系渠道、内容安全提示、隐私说明。
- 游客直接浏览；首发不含微信登录、发帖、支付、完整 DMV。

- V1.1：搜索与筛选增强、图片、浏览记录、收藏、DMV 和更多实用工具。
